# WirelessBatteryTray — 无线设备电量托盘

一个常驻系统托盘的小工具，直接读取 2.4G 无线设备的电量，**不需要打开任何官方驱动软件**。鼠标移到托盘图标上就能看到电量。

内置支持 Akko S9 Ultra 耳机、灵豹 K98 键盘、罗技 G304 鼠标 —— **但这只是三个示例**。项目的读取逻辑是按「VID/PID + HID 读取方式」组织的，**任何 2.4G 无线设备都可以自己加进去**，见文末 [想支持别的设备？](#想支持别的设备)。

平台：Windows 10 / 11

## 内置支持的设备（示例）

| 设备 | 连接方式 | 读取原理 |
|---|---|---|
| Akko S9 Ultra 耳机 | GTAI 2.4G 接收器 (USB VID `36EB` PID `1087`) | 向 HID POS 接口发送查询指令，响应第 5 字节为电量 |
| 灵豹 K98 键盘 | Compx/BY 方案 2.4G+蓝牙 (USB VID `3554` PID `FA09`) | 只读 feature report `0x06`，第 4 字节为电量 |
| 罗技 G304 鼠标 | LIGHTSPEED 接收器 (USB VID `046D` PID `C53F`) | 标准 HID++ 2.0 电池特性 `0x1000` |

> 注意：设备是按 **VID/PID** 匹配的。同型号设备理论上直接可用；不同批次若换了方案，PID 可能不同。

## 使用方法

1. 双击 `dist/WirelessBatteryTray.exe`，任务栏右下角 **^ 溢出区** 会出现一朵樱花图标。
2. **鼠标悬停**图标 → 一行显示三个设备电量，如 `耳机 81% | 键盘 100% | 鼠标 90%`
3. **左键点击** → 弹出详情窗口（带电量条和百分比）
4. **右键** → 菜单：
   - 显示电量详情
   - 立即刷新
   - 开机自动启动（勾选开关）
   - 退出

## 图标颜色 = 该不该充电

托盘图标是一朵樱花，**花瓣颜色代表三个设备中最低的电量**，瞄一眼就知道要不要充电，不用打开任何窗口：

| 花瓣颜色 | 含义 | 建议动作 |
|---|---|---|
| 粉樱（粉色） | 最低电量 > 30% | 正常用 |
| 黄樱（枯黄） | 最低电量 15% ~ 30% | 记得充电 |
| 红樱（红色） | 最低电量 ≤ 15% | 尽快充电 |
| 灰樱（灰色） | 还没读到 / 设备离线 | 检查设备是否开机 |

判定用的是三个里**最低**的那个——任何一个快没电都会体现在花瓣颜色上，不会因为另外两个满电而被掩盖。想看具体是哪个设备低，悬停看数字或点开详情窗。

颜色阈值定义在 `sakura.py` 的 `PALETTES` 和 `palette_for()`，觉得 30%/15% 不合适可以自己改。

## 常见问题

**图标突然变成黄色/红色的樱花了？**
说明三个设备里有一个电量掉到了 30% 以下（黄）或 15% 以下（红）。这是提示你该充电了，不是故障。悬停图标看具体是哪个设备。

**显示"离线"是不是坏了？**
不是。G304 深度休眠/关机时接收器会报告设备不在线，这是正常保护机制，动一下鼠标就能恢复。程序会自动以 8 秒间隔快速重试，设备一上线立刻刷出电量。

**开机后刚进桌面显示"离线"？**
正常。USB 接收器枚举需要一点时间，程序开机自启时会刻意延迟 15 秒再读；即使错过也会自动重试补上。

**会和官方驱动冲突吗？**
不会。它只做只读查询（罗技/灵豹是纯读，Akko 的查询指令不影响播放）。官方驱动可以照常开着，也可以完全卸载。

**刷新频率？**
后台每 30 秒一轮；有设备读不到时自动加速到 8 秒。右键"立即刷新"可手动触发。

## 开机自启

托盘右键 →「开机自动启动」即可。内部按优先级尝试三种方式，成功一种即止（并清理其他方式，避免重复启动）：

1. **计划任务**（最优）：登录后延迟 15 秒启动，失败自动重试 3 次
2. **启动文件夹快捷方式**：带 `--startup` 参数，程序自行延迟 15 秒
3. **注册表 HKCU Run**：兜底

程序有单实例保护（内核互斥体），自启后再手动双击不会开出第二个托盘。移动 exe 位置后下次启动会自动修复自启入口。

## 从源码运行 / 打包

```bash
# 依赖
pip install hidapi pystray pillow pywin32

# 运行
python wireless_battery_tray.py

# 打包单文件 exe（--icon 必须用绝对路径，否则相对会解析到 spec 所在目录）
pyinstaller --onefile --noconsole --icon "D:/path/to/sakura.ico" \
            --name WirelessBatteryTray wireless_battery_tray.py
```

## 项目结构

```
wireless_battery_tray.py   主程序（HID 读取 + 托盘 UI + 自启集成）
sakura.py                   樱花图标绘制（花瓣配色随最低电量变化）
sakura.ico                  exe 图标（16~256 多尺寸）
autostart.py               开机自启管理（计划任务/启动文件夹/注册表三级降级）
selftest.py                命令行自检，打印三设备电量（调试用）
probe_*.py                 协议逆向过程的探测脚本，可供新增设备时参考
tools/                     frida 抓包、字符串提取等逆向辅助工具
```

## 想支持别的设备？

内置的三款设备只是例子。增加新设备不需要改动主程序的 UI、托盘、自启逻辑，**只需要加一个读取类**：

1. `enum_hid.py` 找到设备的 VID/PID 和厂商接口
2. `probe_descriptor.py` 解析报告描述符，确认可用的 report（只读 feature report 是最省事的情况）
3. 协议私有的话，把官方驱动跑起来，用 `tools/hid_hook.py`（frida）抓它实际发的命令，照抄
4. 写一个 `XxxReader` 类（参照 `G304Reader` / `K98Reader` 的骨架），加进 `READERS` 列表即可

公开协议的设备可以直接套模板（罗技 HID++、蓝牙 HID 电池用法页）。欢迎提 PR 把你的设备加进来。
